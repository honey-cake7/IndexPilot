## M7 — Workload-aware optimization engine

**1. What was built:** a pure greedy selector using actual complete-set HypoPG evaluations, saved representative query frequencies, a hard additional estimated-byte budget, optional heuristic write penalties and baseline-relative per-query regression limits. Outputs include selected order, candidate outcomes, objective components, per-step marginal scores/query changes, stop reason and final fresh verification. POST/GET/list optimization APIs and migration 0007 persist normalized history linked to M6 evidence.

**2. Why it matters:** useful indexes compete for storage and can overlap in benefit. M7 makes a workload-level choice, evaluating each current-set-plus-candidate combination rather than adding isolated percentage improvements. It supplies a traceable estimated selection for M8's later recommendation explanations without making runtime or optimality claims.

**3. DBMS concepts:** frequency-weighted root plan costs; marginal rather than standalone benefit; hard estimated storage constraints; heuristic write-maintenance preferences; query regressions versus aggregate improvements; local versus global optima; normalized foreign-keyed selection/trial history and atomic metadata transactions. Greedy can miss pairs with no individual benefit; unit fixtures demonstrate that limitation explicitly.

**4. Implementation:** optimizer/objective.py recalculates weighted costs from query roots and actual member bytes, applies the optional penalty and checks budget/regression limits. greedy.py evaluates complete rounds and uses gain per additional byte, absolute gain, signature and UUID for deterministic ranking. models.py validates settings/results independently of FastAPI. service.py holds a fresh M6 context throughout the search, records evaluated sets and verifies cleanup. persistence.py saves M6 evidence and optimizer run/outcome/trial rows in one outer metadata transaction; api/optimization.py exposes POST/GET/list. The evaluator now supports a bounded configurable private cache and explicit uncached refresh.

**5. Technical decisions:** all source queries participate in every trial; unknown/zero/negative member sizes never count as free storage; nonpositive incremental bytes are conservatively rejected. Defaults are eight selected indexes and 128 evaluator calls; one uncached final call is reserved, and a round cannot start unless every remaining alternative fits the allowance. This prevents partial-round order bias. Final cost/size drift, invalid estimates or database failures abort selection publication. The optional write penalty defaults to zero, uses user weights/scenario basis, and is never labeled measured write latency. Read improvement remains separate from penalized net gain. Optional exhaustive search is deferred; M8 application work has not begun.
